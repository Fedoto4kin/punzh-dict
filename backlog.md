## 1. Связи «от» и тип `ArticleLink.kind` — **параллельно**

Отдельный контур разметки HTML/связей; не блокирует AI-поиск.

**Цель:** связать деривации `от X` через `ArticleLink` и различать типы
отсылок: **см.** / **ср.** / **от**.

### Инвентаризация (прод, 2026-08, `audit_see_refs`)

| Корзина | Хитов | Статей |
|--------|------:|-------:|
| `<i>freq\|caus\|mom\|refl</i> от lemma` | 729 | 728 |
| прочее `от lemma` (`deriv_loose`) | 35 | 35 |

Кривых маркеров см/ср: 0. Отдельный паттерн «см от X» в бэклоге — уточнить
вторым прогоном; основная масса — tagged + loose.

### Модель

На `ArticleLink` поле `kind`:

| kind | HTML | Смысл |
|------|------|--------|
| `see` | `<i>см.</i> X` | отсылка «смотри» (дефолт для старых связей) |
| `cf` | `<i>ср.</i> X` | сравнение |
| `deriv` | `<i>freq\|…</i> от X` или loose `от X` | деривация |

`unique_together` по-прежнему `(from_article, to_article)` — одна дуга, один kind.

### Поведение

- **Поиск / кластер / онтология (наследование поля):** только `see` и `cf`.
  `deriv` в общий кластер «см.» не входит.
- **Админка:** вид kind на исходящих связях; autocomplete цели уже есть.
- **Подсветка `от X` на сайте:** отдельный шаг (не блокер связей в БД).

### Шаги

1. ~~Инвентаризация HTML~~ (`audit_see_refs`).
2. ~~`kind` + миграция; бэклог существующих связей `see`/`cf` из HTML.~~
3. ~~Резолв `от X` (ok / омоним / miss) — отчёт~~ (`check_deriv_links`).
4. ~~Автосоздание однозначных `deriv`; интерактив для омонимов/дыр~~ (`fix_deriv_refs`).
5. Админка / подписи; при необходимости подсветка и «см от».

**Команды (локально / прод, контейнер `punzh_django` / `punzh_web`):**

```bash
# отчёт (ожидание на дампе: ok 712, hom 48, miss 4, already 0)
python manage.py check_deriv_links --examples 10

# авто ~712
python manage.py fix_deriv_refs --apply-unique --dry-run
python manage.py fix_deriv_refs --apply-unique

# вручную ~52 (нужен TTY: docker exec -it …)
python manage.py fix_deriv_refs --queue homonym
python manage.py fix_deriv_refs --queue unresolved
```

**Не смешивать** с очередью правок см./ср. (`check_article_links` /
`fix_see_refs`) без фильтра по `kind`.

## 2. Очистить переводы
**Проблема:**
Переводы сейчас избыточны, потому что раньше не было векторного поиска.
Пример: статья *hotkoi* содержит множество однотипных переводов:

- быстрый
- легкий
- легкий на ход
- пользующийся
- пользующийся спросом
- скорый
- спросом
- ход
- ходкий

Особенно замусорены формы глагола **быть** и **становиться**.

**Задача:**
Сделать LLM‑очистку переводов (скрипт `app/agents/clean_translations.py`,
промпт `agents/translation_cleanup.py`, DeepSeek). Пилот — **dry-run** (по
умолчанию): отчёт в `agents/data/*.json`, БД не меняется.

- объединить дублирующиеся значения;
- убрать обрывки и вспомогательные осколки («ход», «спросом», «быть» /
  «становиться» **в чужих** статьях, где они не перевод леммы);
- **не** вырезать «быть» у самой леммы olla и подобных: «быть»,
  «существовать», «находиться», «иметься», связка и всп. — отдельные
  эквиваленты (см. `agents.translation_cleanup.SYSTEM_PROMPT_CLEAN_TRANSLATIONS`);
- у союзов/частиц/предлогов — только эквиваленты служебной леммы;
- оставить семантические ядра и устойчивые фразы для поиска;
- привести к формату полнотекстового поиска.

**Проблема в поиске:**
Поиск по «быть» не предлагает уточнений → нужно добавить **prio‑фильтр**.

### Пилот и prod

Подробно: **`docs/translation_cleanup.md`**.

- Dry-run: `clean_translations.py --id …` / `--word …`; автодокат в `--out`;
  `--force` — перепроцессить id.
- Prod: контейнер **`punzh_web`**; dry-run (nohup) → json → `--write --from-json`.
- Миграция **`0027`** (`ArticleIndexTranslateSnapshot`) перед первой заливкой.
- Статьи **без** строк в `ArticleIndexTranslate` не обрабатываются.

**Контрольные id после правок service-word:** 10786 (`a`), 1475 (`da I`),
1477 (`dai`), 8992 (`olla`), 4469, 7636, 1717.

### Поиск после очистки переводов — **готово (2026-08)**

Контракт UX: `docs/searching_upgrade.md` §0.1. Тесты: `test_search_filter.py`, `test_search_korova.py`.

**Эталон «быстро»** — `docs/searching_upgrade.md` §0.1, `ruttoh` / `ehatta` /
`maihahtua` / `rutoldi`. Семантика `?f=exact` = `find_exact_match_ids`
(ILIKE на всю строку `rus_word`, не подстрока).

**Эталон «корова» / `enži|kandon'e` (id 1717)** — после cleanup:

| Запрос | Полная выдача | `?f=exact` | Примечание |
|--------|:-------------:|:----------:|------------|
| первотельная | да (FTS) | нет¹ | если в индексе только «первотельная (о корове)» |
| первотельная корова | да | да | ILIKE на целую строку |
| корова | да (FTS) | **нет** | в индексе **нет** голого «корова» |

- При «корова» — сужающий тег (~«первотельная» / «первотельная о корове»),
  клик `?f=…` оставляет `enži|kandon'e` среди прочих с «первотельная».
- Cleanup: держать `(о корове)` в `rus_word`; **не** индексировать «корова»
  отдельно (см. `translation_cleanup.py`, скобки).

**Закрыто (2026-08):** эталоны быстро/корova, prio «быть», ярлыки тегов, `--force`.

Опционально: стеммер, fuzzy (`docs/backlog-search.md`, низкий приоритет).

**Уроки пилота (2026-08, исправлено в промпте/sanitize):**

- `l'is'||t'ie`: параллель «лучины для плетения лаптей, корзин и пр.» →
  `_ensure_i_pro_parallel_phrases`, не «корзин и пр.»; глаголы не терять.
- `bašk||a`: согласование в промпте («крупного сома», не «крупной сома»).

¹ Exact для «первотельная» — только при отдельной строке `rus_word` =

## 3. Поиск неразмеченных помет и помет вне `<i>`

Найти все случаи:

**Решение:**
Скрипт:

- ищет все слова из списка помет;
- проверяет наличие `<i>`;
- предлагает исправление.
