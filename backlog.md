## 1. Связи «от» и тип `ArticleLink.kind` — **параллельно**

Отдельный контур разметки HTML/связей; не блокирует AI-поиск.

**Цель:** связать деривации `от X` через `ArticleLink` и различать типы
отсылок: **см.** / **ср.** / **от**.

### Инвентаризация (прод, 2026-08, `audit_see_refs`)

| Корзина | Хитов | Статей |
|--------|------:|-------:|
| `<i>freq\|caus\|mom\|refl</i> от lemma` | 729 | 728 |
| прочее `от lemma` (`deriv_loose`) | 35 | 35 |

Кривых маркеров см/ср: 0. Отдельный паттерн «см от X» в бэклоге — уточнить
вторым прогоном; основная масса — tagged + loose.

### Модель

На `ArticleLink` поле `kind`:

| kind | HTML | Смысл |
|------|------|--------|
| `see` | `<i>см.</i> X` | отсылка «смотри» (дефолт для старых связей) |
| `cf` | `<i>ср.</i> X` | сравнение |
| `deriv` | `<i>freq\|…</i> от X` или loose `от X` | деривация |

`unique_together` по-прежнему `(from_article, to_article)` — одна дуга, один kind.

### Поведение

- **Поиск / кластер / онтология (наследование поля):** только `see` и `cf`.
  `deriv` в общий кластер «см.» не входит.
- **Админка:** вид kind на исходящих связях; autocomplete цели уже есть.
- **Подсветка `от X` на сайте:** отдельный шаг (не блокер связей в БД).

### Шаги

**Сделано (2026-08):** инвентаризация (`audit_see_refs`), поле `kind` + миграция,
отчёт `check_deriv_links`, автосоздание однозначных `deriv` + интерактив
(`fix_deriv_refs`).

**Осталось:**
- ~~Админка: kind на исходящих/входящих связях~~ (inline в `dict/admin.py`).
- Подсветка `от X` на сайте.
- Паттерн «см от X» — уточнить вторым прогоном.

**Команды (локально / прод, контейнер `punzh_django` / `punzh_web`):**

```bash
# отчёт (ожидание на дампе: ok 712, hom 48, miss 4, already 0)
python manage.py check_deriv_links --examples 10

# авто ~712
python manage.py fix_deriv_refs --apply-unique --dry-run
python manage.py fix_deriv_refs --apply-unique

# вручную ~52 (нужен TTY: docker exec -it …)
python manage.py fix_deriv_refs --queue homonym
python manage.py fix_deriv_refs --queue unresolved
```

**Не смешивать** с очередью правок см./ср. (`check_article_links` /
`fix_see_refs`) без фильтра по `kind`.

## 3. Поиск неразмеченных помет и помет вне `<i>`
**Задача:**
Найти все случаи:

- помет без `<i>`
- помет внутри текста без тега
- помет с ошибками в орфографии
- помет с латиницей вместо кириллицы

**Решение:**
Скрипт:

- ищет все слова из списка помет;
- проверяет наличие `<i>`;
- предлагает исправление.

снятие «лишних» полей из иллюстраций; фильтр `/ontology/` и AI-поиска по
`from_translation`.
