# План: верификация LLM-классификации

Статус: рабочий документ. Предшественник — тематическая классификация
(`research/studia-nordica/`). Метод разметки в продукте —
`docs/method-onthlogy-markup.md`.

---

## 1. Цель

Оценить достоверность, воспроизводимость и ограничения автоматической
тематической классификации словарных статей с помощью LLM при опоре на
русскоязычный семантический слой словаря Пунжиной.

Не цель: заново спроектировать каталог или массово переразметить словарь
«лучше». Пересмотр каталога — только как *результат* анализа пробелов, не
как параллельная перестройка.

---

## 2. Исследовательские вопросы

1. Насколько корректно LLM относит статьи к тематическим полям?
2. Как автоматическая разметка согласуется с независимой экспертной?
3. Какие поля наиболее / наименее надёжны?
4. Частота лишних и пропущенных категорий?
5. Устойчивость при повторной обработке той же статьи?
6. Зависимость от модели (после стабилизации протокола на одной модели)?
7. Влияние перевода леммы, иллюстраций и карельского материала?
8. Какие типы статей требуют обязательного эксперта?

---

## 3. Два объекта оценки (не смешивать в одной «точности»)

| Объект | Вопрос | Как мерить |
|--------|--------|------------|
| **A. Классификатор** | При *фиксированном* каталоге из 28 полей — насколько LLM совпадает с экспертами | Precision / Recall / F1, Macro-F1, Jaccard; только статьи, где эксперт смог выбрать поле(я) из каталога |
| **B. Каталог** | Насколько 28 полей покрывают материал; где дыры и вынужденные соседние ярлыки | Доля «ни одно поле» / «недостаточно информации»; качественный разбор; *не* считать ошибкой модели |

Ошибка понимания значения ≠ ошибка границы категорий (стык зон).

---

## 4. Эталон и baselines

- **Gold:** независимая экспертная разметка (2 человека; при разногласии —
  третий или joint resolution). LLM-результаты экспертам **не** показывать.
- **Не gold:** текущие `ArticleSemanticField` в БД (продукт той же методики).
- **Контроль (crowd):** опрос посетителей на сайте — 3 статьи (s/v/a/adv,
  с переводом, непустое тело); ответы в `ClassificationSurveyResponse`.
  Сравнивать с expert/LLM, **не** смешивать с gold.
- **Baseline / reproducibility:** сравнение повторного LLM-прогона с уже
  залитой разметкой и с самим собой (реплики).

Предметные пометы словаря (`Tag`, чаще `type=3`: с.-х., ботаника и т.п.) —
дополнительное сопоставление, **не** замена экспертов. Нужен ручной
whitelist предметных ярлыков (тип 3 смешивает стилистику и предмет).

---

## 5. Выборка

Целевой ориентир цикла: **~350–500** статей после пилота инструкций.

| Слой | Ориентир | Назначение |
|------|----------|------------|
| Случайная контрольная | 200–300 | Оценка «как на словаре в целом» |
| Целевая сложная | 100–150 | Стыки полей, полисемия, толстые статьи, кандидаты в `no_field` |
| Пилот инструкций | 40–50 | До основной разметки; правка гайда |

Стратификация (уточнить после фазы 0): наличие перевода; POS (s/v/a);
число переводов; наличие иллюстраций; уже проставленные поля /
`from_translation`; предметные пометы.

Отбор и id выборки фиксировать в `data/` (версия словаря + дата среза).

---

## 6. Экспертная разметка

Подробности — `annotator-guidelines.md`.

Кратко:

- закрытый каталог 28 полей + определения из статьи / `SemanticField`;
- 0–3 поля на статью; допустимы «ни одно поле» и «недостаточно информации»;
- фиксировать уверенность, основание (перевод / пример / оба), неоднозначность;
- согласие экспертов анализировать (Krippendorff α или аналог для multi-label),
  не только «сводить к истине».

---

## 7. Метрики

Multi-label:

- Precision, Recall, F1 (micro / macro);
- Jaccard по множествам полей статьи;
- те же метрики **по каждому** из 28 полей;
- отдельно: случайная vs целевая; простые vs сложные;
- inter-annotator agreement.

Качественно — типы ошибок (§10 исходного концепта):

1. лишняя категория;
2. пропущенная категория;
3. ошибка интерпретации перевода;
4. ошибка контекста примера;
5. ошибка границы категорий (соседнее поле);
6. неоднозначность источника;
7. недостаточность каталога.

---

## 8. Эксперименты по входу (после gold)

| Вариант | Вход | Примечание |
|---------|------|------------|
| A | Только переводы леммы | Близко ко второму проходу / ядру |
| B | Переводы + русские фрагменты примеров | Как широкий проход в статье |
| C | + карельский материал статьи | Проверка риска ложных сближений с фин./эст. |
| D | Экспертная интерпретация носителем/специалистом говора | Отдельный модуль; без специалиста не блокировать A–C |

Флаг `from_translation` в БД — готовая ось «ядро из перевода vs только широкий
проход» без полного перепрогона; использовать в разборе, не путать с A/B.

Воспроизводимость: сначала **одна** модель, низкая температура, 2–3 реплики;
затем другая модель / paraphrasing промпта — отдельной серией.

Логировать: модель+версия, дата, system/user prompt, параметры, сырой ответ,
нормализованные поля.

## 10. Предостережения (из концепта + статьи)

1. Не строить эталон другой LLM по тем же правилам.
2. Не считать онтологию из 28 полей абсолютной истиной — но и не ломать её
   по ходу атрибуции; adequacy каталога учитывать отдельно.
3. Не требовать единственного правильного набора полей там, где стык зон
   осознан принципами классификации.
4. Не выводить «языковую картину мира» карелов из русской проекции без
   варианта D и оговорок первой статьи.
