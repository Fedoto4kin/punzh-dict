## Главный принцип: ПРОЗРАЧНОСТЬ и доверие

Пользователь всегда понимает, ЧТО система поняла и ПОЧЕМУ показала это.
«Умный поиск» не должен быть чёрным ящиком — иначе ему не доверяют. Отсюда:
разбор запроса виден, группы объяснены подписями, всегда есть выход к
буквальному поиску.

## Отдельная страница

AI-поиск — своя страница `/ai-search/`. Обычный поиск остаётся простым и
быстрым, не меняется. На закрытой альфе **без ссылки с главной и из шапки**
(как скрытый URL); вход только по прямой ссылке. Позже — осознанный пункт
«умный поиск» в навигации.

## Ввод: естественный язык; доверие — к осям на выходе

Строка запроса **широкая**: исследовательские формулировки допустимы и желательны
(«Найди все слова связанные с разведением коз», «как сказать…», опечатки).
Служебную оболочку («найди», «все слова», «связанные с», «по-карельски») модель
кладёт в `dropped`, смысл — в `lexical` / `fields` / `tags`.

**Не** вычищать такие фразы на входе до LLM и **не** требовать «только леммы».
Защита от промпт-инъекций — не урезанием UX, а контрактом выхода:

- `fields` / `tags` / `dialect` — только из закрытых справочников БД;
- лимиты на длину запроса и на свободные строки (`lexical`, `dropped`, `display`);
- при мусоре / сбое — fallback на лексический поиск;
- `display` по возможности собирать из уже проверенных осей.

Полностью «закрыть» инъекции у LLM нельзя: модель не пишет в БД и не вызывает
инструменты; ущерб сводится к кривым осям или подписи — их отсекает валидация.

## MVP (первая версия)

### 1. Строка запроса + разбор (прозрачность)
Под строкой — как понят запрос: «искали: ругаться · брань; „по-карельски"
пропущено». Пометы в расшифровке — **именами словаря** («verbum, глагол»),
не краткими кодами (`v`). Если модель выделила ответ на вопрос (`focus`,
напр. «чем режут хлеб» → нож) — строка «В фокусе: …» (ранжирование;
не путать с «рядом по теме»). Пользователь видит, верно ли понято.
Всегда рядом — «искать буквально» (fallback одним кликом).

### 2. Разбор моделью
Русский запрос → модель (YandexGPT через шлюз) раскладывает на оси: смысловые
поля + пометы + говор. Исправляет опечатки, отбрасывает служебное
(«по-карельски», «найди все слова…» и т.п. — в `dropped`).
**Пометы** (части речи, стилистика, areal, говор) — закрытые фильтры, не
темы: «глаголы в приметах» → `tags` AND, без смыслового «рядом по теме»
от пометы. Контракт JSON и валидация — `docs/SPEC_ai_query_parse.md`.

### 3. Поиск + группы по ПРИРОДЕ попадания (одноуровневые)
Результаты — группами, ранжированными по природе попадания (это И порядок, И
объяснение — прозрачно):
1. ПРЯМОЕ лексическое (нашли само слово-значение) — высший ранг, основной ответ.
2. По ПОМЕТЕ (бранное, грубо, ботаника...) — слова, что ЯВЛЯЮТСЯ искомым.
3. По смысловому ПОЛЮ (классификация статьи) — тематически близкие.
4. (опц., если keywords залиты) через ИЛЛЮСТРАЦИЮ — «в выражениях», с
   контекстом («в поговорке о громе „дед бранится"»), как НАХОДКА внизу, чтобы
   не спутать с прямым значением.

Каждая группа — ЧЕЛОВЕЧЕСКАЯ подпись («Слова со значением „ругаться"»,
«Бранные и грубые»), НЕ внутрянка. Внутри — плоский список, 2-3 примера +
«ещё N» (свернуть). Порядок групп = убывание релевантности.

### 4. Fallback (обязателен)
Модель недоступна / шлюз лёг / разобрать не удалось / выдача пуста → тихо
откатиться на обычный лексический поиск, показать: «по смыслу не нашли, но
есть совпадения по словам…». AI-недоступность НЕ ломает страницу.

### 5. Связанные статьи — через ArticleLink (как в обычном поиске)
Статьи-отсылки «см. X» (варианты написания: l’ihota → см. l’ihuo) сами в
no_field (своего смысла нет). Их НЕ надо отдельно классифицировать: при выдаче
AI-поиск прогоняет найденные статьи через тот же механизм `ArticleLink`, что и
классический поиск — связанные подтягиваются автоматически на лету. Отсылка
находится через своего донора, поля не копируются в БД (связь одна, в
ArticleLink). Тот же приём на закрытой бете просмотра поля (`/ontology/<id>/`):
неразмеченная отсылка показывается в поле целевого слова.

## Ранжирование (MVP)

По ПРИРОДЕ попадания (прозрачно, объяснимо — одно решает и порядок, и
«почему»):
- прямое лексическое > помета в тему > смысловое поле > keyword-иллюстрация;
- бонус за совпадение нескольких осей (слово И поле И помета — выше).
НЕ ML-ранжирование — детерминированно и объяснимо пользователю
(`focus` / exact-перевод ≫ lexical; `?sort=relevance|alpha`, см. `dict/ai/rank.py`).

## Перспектива (НЕ в MVP)

- **Подгруппы по смысловому полю ВНУТРИ группы** — УСЛОВНО: только если слова
  группы входят в РАЗНЫЕ поля (иначе плоско, без вырожденной вложенности).
  Пример: «бранные» → про характер / про речь / эмоциональные. Порог (сколько
  полей, сколько слов на подгруппу) — настроить на реальных данных.
- **«Похожие запросы, которые могут быть интересны»** — рядом с разбором. Два
  источника: синонимы прямых попаданий (лексические, бэклог П1) + смежные
  смысловые поля (семантические). Различать подачей: «другие слова того же
  смысла» vs «пойти в соседнюю тему».
- **Семантическое древо / «пройти дальше»** — от групп ветки в смежные поля.
  Дозированно (2-3 направления, не всё дерево — иначе paralysis of choice).
  Исследование словаря для тех, кто не знает, что искать.
- **Карельское в русской транслитерации** (из Метрики: «иел», «кондега»,
  «ваштакаба», «йовло»…) — распознать токен, прогнать **формальные** правила
  кириллица→латиница словаря, предложить «возможно вы искали …» (рядом с
  разбором / в fallback). Не смешивать с LLM-угадыванием; не в текущем MVP.

## Примеры опыта

**«как ругаться по-карельски»**
Разбор: искали «ругаться · брань»; «по-карельски» пропущено.
- Группа «Слова со значением ругаться»: čakkiačie, kirota, +ещё.
- Группа «Бранные и грубые» (по пометам).
- (перспектива) Находка: ukko yrrotäy — «дед бранится» в поговорке о громе
  (через keyword, помечено как образное, чтобы не спутать).

**«Найди все слова связанные с разведением коз»**
Разбор: искали «коза · разведение» (+ поле вроде животноводства/быта);
«найди / все слова / связанные с» пропущено. Не пустой fallback и не отказ
из‑за «лишних» слов в запросе — это нормальный исследовательский ввод.

**«чем режут хлеб в Весьегонске»**
Разбор: резать · нож · хлеб; говор весьегонский.
- Группа по полю (Физические действия / Предметы / Пища) ∩ говор весьегонский.
- Fallback, если в весьегонском пусто: показать по словам без фильтра говора.

**«da» / служебное**
Разбор: зацепок нет → сразу буквальный поиск (fallback), без пустых групп.

## Готовность (данные vs код)

Раньше блокерами были очищенные переводы и классификация. **По данным готовы**
(dev/prod, 2026-10); код MVP — закрытая альфа на prod:

| Предпосылка | Статус |
|-------------|--------|
| Cleanup `ArticleIndexTranslate` | сделано (prod 2026-09); опц. аудит индекса — не блокер MVP |
| Онтология `SemanticField` + привязки | ~28 полей, ~14.7k статей с полями, keywords залиты |
| `from_translation` массово | сделано; AI-поиск по флагу **не** фильтрует |
| Лексический `/search/` | baseline готов, fallback возможен |
| Шлюз Timeweb + `parse_query` | канал есть; разбор JSON есть |
| `manage.py ai_query`, retrieval, `/ai-search/` async | **на prod** (закрытая альфа) |

Не блокеры альфы: beta-логи, пункт в меню, повторный LLM-cleanup, чистка
keywords, фильтр по `from_translation`, эмбеддинги (этап 2).
