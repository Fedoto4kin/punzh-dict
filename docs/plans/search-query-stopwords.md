# План: стоп-токены в многословном русском поиске (вариант A)

Статус: **бэклог** (лексический `/search/`, не AI).  
Связь: `docs/backlog-search.md` §P1-stop, `docs/plans/INDEX.md`.

## Проблема

Русский запрос → ILIKE + **токенный OR**: статья попадает, если в `rus_word`
есть **хотя бы один** токен запроса.

На «о корове» / «при …» служебное слово (`о`, `при`) даёт тысячи попаданий
из помет `(о корове)`, `(при ком-л.)` и т.п. Смысловой токен тонет в шуме.

`STOPWORDS` уже есть, но режет только **ключ сужающего тега**, не seed OR.

OR для смысловых слов оставляем: «вон там» → и голые «вон»/«там», и фраза
(`test_search_token_regression`).

## Решение (вариант A)

В многословном запросе (≥2 токена) в token-OR участвуют только **не-стоп**
токены. Однословный «о» / «при» — без изменений.

| Запрос | Поведение |
|--------|-----------|
| `о корове` | только `корове` (+ fuzzy) |
| `вон там` | оба токена (не стопы) |
| `о` | ищем `о` |
| оба токена — стопы | ILIKE фразы **или** OR стопов (не пустая выдача) |

Корзина **1c** (`при`, `для`, `без`, …) — по DF корпуса, не слепой NLTK-список.

## Шаги

1. `manage.py audit_query_stopwords --min-df 30 --top 60 --suggest`  
   (уже есть: `dict/query_stopword_audit.py`) → ручной отбор `_STOP_1C`.
2. В `rus_search_core` / `_translate_q_any_query_token`: фильтр стопов при ≥2 токенах.
3. Тесты: «о корове» ≈ «корове»; регрессия «вон там»; однословные стопы.
4. Документировать в `docs/searching_upgrade.md` §0.1.

## Не делать здесь

AND по всем токенам; AI-разбор; стеммер (P3); смена семантики `?f=exact`.
