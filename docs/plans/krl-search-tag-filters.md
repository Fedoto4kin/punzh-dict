# План: фильтры по пометам в карельском `/search/`

Статус: **в работе**.  
Связь: лексический `/search/` (KRL), не AI; не трогать русский `?f=` и `/tags/`.

## Проблема

Карельский поиск по подстроке заголовка часто даёт много хитов без способа сузить
по пометам (часть речи, говор, стилистика и т.д.). На предметном указателе
`/tags/` пометы уже сгруппированы по `Tag.type`, но это отдельный контур.

## Решение

В ветке `direction == "krl"` — фасетные фильтры по `ArticleIndexTag`:

| Правило | Деталь |
|---------|--------|
| Группы | type 1–4 radio-чипы; type 5 — отдельный чекбокс `?ph=1` |
| Выбор | ≤1 помета на группу (radio); AND между группами и с `ph` |
| Грамматика | type=2: только родители `level=0`; дочерние (`comparativus` и т.п.) не в UI |
| Фразеологизмы | чекбокс «словарные статьи с фразеологизмами» = любая помета type=5 |
| Видимость группы | ≥2 разных пометы типа в фасет-базе; нет / все одинаковые → скрыть |
| Видимость `ph` | есть и с фразеологизмами, и без (или уже включён) |
| Блок целиком | ≥1 группа или чекбокс `ph`, и выдача «широкая» |
| URL | `?t=<id>[,<id>…]` и/или `?ph=1`; пагинация сохраняет оба |

Фасет-база для группы G: KRL-хиты ∩ фильтры **других** групп (не своей).

Родитель не раскрывается в OR по дочерним: фильтр — по id в индексе.
